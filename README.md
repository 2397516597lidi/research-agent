# 自动调研 Agent

给定一个研究主题，Agent 自主完成「搜索 → 筛选 → 阅读 → 成文」，产出一份带可核验出处的调研报告。

## 效果

10 个主题的评测结果：

| 指标 | 结果 |
|---|---|
| 任务成功率 | 10 / 10 |
| 平均步数 | 8.3 步 |
| 平均耗时 | 38.9 秒 |
| 单篇引用数 | 10 ~ 30 条 |

成功率判定标准：产出报告 ≥ 300 字、引用 ≥ 5 条、分节 ≥ 3 个、不以「资料不足」收尾。
**这是格式合规率，不是内容正确率**——内容真实性靠人工抽查（已抽 2 处，均与原文一致）。

### 同主题二次运行

| 指标 | 第一次 | 第二次 | 变化 |
|---|---|---|---|
| 步数 | 7 | 6 | −1 |
| 搜索次数 | 4 | 3 | −1 |
| 读页次数 | 11 | 6 | **−45%** |
| 耗时 | 48.8s | 33.1s | **−32%** |

第二次启动时加载 8 篇已读清单，`search_web` 过滤掉这些 URL，模型转而搜索新角度（市场规模 / 信通院），读了 6 篇全新资料，报告结构未退化。

## 架构

```
主题
→ 拆 2~3 个关键词方向，分别 search_web
→ 三道筛：相关性 ≥1.5、来源权威 ≥3、时效 180 天内
→ search_web 只返回 600 字摘要，供模型判断相关性
→ 模型判断值得细读的，调 read_page 取正文（单次 2000 字，可翻页）
→ 循环，直到模型认为资料足够
→ 生成 markdown 报告，论断后标 [编号]
→ rebuild_refs 用报告正文编号重建来源列表
→ save：把本次读过的页面存进 memory/ 下的 json
→ 下次同主题启动时 load，注入 system 并过滤已读 URL
```

## 关键设计

### 1. 两档取材，而不是一次全塞

`search_web` 只返回摘要（约 600 字），`read_page` 才返回正文（2000 字/次，带 `start` 翻页）。

实测一个主题 3 次搜索、12 次读页，累计约 2 万字。如果搜索时就把正文全带上，同样的信息要 6~8 万字。

### 2. 引用列表由程序生成，不由模型生成

模型写正文时标 `[编号]`，但列来源列表时会自己从 1 重排，导致正文 `[21]` 在列表里找不到。

修法：`rebuild_refs` 从正文按出现顺序提取编号，查 `POOL` 取 URL，重新生成列表。模型编造的编号（超出池子范围）单独标记为「来源不存在」。

**这是用代码保证一致性，不靠提示词约束模型。**&#8203;

### 3. 每次 run 重置编号池

`POOL` 和 `_next_idx` 是模块级全局变量。批量评测时如果不重置，编号会跨主题累积。

更危险的是：模型编造的编号可能**恰好撞上上一个主题的编号**，从而配上一个真实但完全无关的 URL——这种错误永远查不出来。

### 4. 跨任务记忆：按主题复用已读清单

`memory.py` 把「读过哪些页面」按主题存成 json（URL + 标题 + 200 字摘要，不存全文）。

三个环节：

- **写**：`read_page` 每读一篇，往 `CURRENT["mem"]` 里加一条（同一 URL 不重复）
- **读**：`run()` 开头 `load`，用 `digest()` 生成已读清单拼进 system prompt
- **用**：`search_web` 过滤掉已读 URL，逼模型换角度搜索

`CURRENT` 是全局变量，因为工具函数由模型通过 `fn(**args)` 间接调用，参数里塞不进记忆对象。

实测二次运行读页从 11 降到 6，耗时从 48.8s 降到 33.1s，且模型改为搜索新关键词，报告结构未退化。

## 踩过的坑

| 问题 | 现象 | 根因 |
|---|---|---|
| 参数校验错 | `search_web() got an unexpected keyword argument 'idx'` | `TOOLS` 里 `required` 写成 `["idx"]`，正确应为 `["query"]` |
| 编号跨主题累积 | 第 8 个主题的引用编号到 176 | `_next_idx` 未重置 |
| 正文与列表编号不一致 | 正文 `[21]`，列表只有 18 条 | 模型自己重排列表，用程序重建解决 |
| 引用幻觉 | 正文出现 `[32]`，但池子只有 24 条 | 模型自行编号，由 `rebuild_refs` 标记为缺失 |
| 评测数据失真 | 第二次跑 eval，10 个主题全部变快 | 记忆命中历史记录，`eval.py` 开头需清空 `memory/` |

## 局限

- **记忆只做同主题复用**：不跨主题语义检索，换一个主题就完全从零开始
- **无缓存**：同一 URL 在多次主题评测中会被重复请求，未做本地缓存
- **无成本统计**：未记录每次调用的 token 消耗
- **内容真实性依赖人工抽查**：程序只能保证「编号对得上」，不能保证「URL 里真有那句话」

## 文件

| 文件 | 作用 |
|---|---|
| `agent.py` | 主流程：工具定义 + Agent 循环 |
| `search_layer.py` | 搜索层：接口调用 + 三道筛 |
| `refs.py` | 引用重排：从正文编号重建来源列表 |
| `memory.py` | 跨任务记忆：按主题存取已读页面 |
| `eval.py` | 批量评测 10 个主题 |
| `check.py` | 验证引用完整性 |
| `reports/` | 各主题生成的报告 |
| `memory/` | 各主题的记忆文件（运行时生成，已 gitignore） |

## 运行

```bash
pip install requests
set DEEPSEEK_API_KEY=sk-...

python agent.py    # 跑单个主题
python eval.py     # 批量评测 10 个主题
python check.py    # 验证引用完整性
```
